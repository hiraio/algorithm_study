# BOJ 14469 — 소가 길을 건너간 이유 3

- **날짜**: 2026-06-12 (금)
- **유형**: 그리디 (정렬 + 한 번 훑기), 단일 자원 스케줄링
- **결과**: 자력 AC (재풀이, 풀이 잘 떠오름)

## 핵심 테크닉

검사대 1개로 모든 소 검사를 끝내는 최소 시각.

1. **도착 시각 오름차순 정렬** — 먼저 온 소부터 검사하는 게 최적 (늦게 올 소를 먼저 기다릴 이유 없음)
2. `t` = "검사대가 다음에 비는 시각"을 들고 순회, 두 경우 분기:
   - `도착시각 < t` (소 도착했는데 검사대 바쁨) → 소가 기다림: `t += run`
   - `else` (검사대가 먼저 빔 → 소 기다림): `t = 도착시각 + run`
3. 마지막 `t` = 답

## 잘한 부분

- 정렬 기준(도착 시각)과 분기 로직을 정확히 세움
- 경계 `도착시각 == t`: else로 가도 `t = 도착시각 + run = t + run`, if의 `t += run`과 결과 동일 → `<`/`<=` 무관 (두 식이 같은 값이라 안전, 운 아님)

## 1781(컵라면)과 비교

- 1781은 "용량 관리"라 min-heap 필요. 14469는 **정렬 후 1-pass**로 끝나는 더 가벼운 그리디.
- 공통 교훈: **그리디는 "무슨 기준으로 정렬하느냐"가 절반.** 1781=마감일, 14469=도착시각.

## 배운 점

- 단일 자원(검사대 1개) 스케줄링 = 도착순 정렬 + "자원이 비는 시각" 추적. 두 문제 연속 풀이로 "정렬 기준 잡기"가 그리디의 핵심임을 체감.
