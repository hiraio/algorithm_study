# BOJ 1700 — 멀티탭 스케줄링

- **날짜**: 2026-07-02 (목)
- **유형**: 그리디 (Belady / offline optimal — "미래에 가장 늦게 쓰이는 것을 버린다")
- **결과**: AC (디버깅 3라운드 후)

## 핵심 아이디어

구멍 N개짜리 멀티탭에 기기를 순서대로 꽂아야 함. 꽉 찼는데 새 기기를 꽂아야 하면 하나를 뽑아야 하고, 이 "뽑는 횟수"를 최소화.

- **정답 전략 = 지금 꽂혀 있는 것들 중, 앞으로 가장 늦게(또는 다시는) 쓰이지 않는 것을 뽑는다.** (캐시 교체의 Belady 최적 알고리즘과 동일 — 오프라인이라 미래를 다 알기 때문에 가능)
- 세 갈래 판단:
  1. 이번 기기가 **이미 꽂혀 있음** → 아무것도 안 함
  2. **빈 구멍이 있음** → 그냥 꽂음 (뽑기 카운트 X)
  3. **꽉 찼고 안 꽂혀 있음** → 미래 사용 시점이 가장 먼(또는 없는) 구멍을 뽑고 그 자리에 꽂음, `ret++`

## 막혔던 포인트 (디버깅 3라운드)

이 문제는 알고리즘보다 **`=` vs `==`와 플래그 설계**에서 삽질함.

### 1라운드 — `=`/`==` 오타 2개 (서로 반대 방향)

```cpp
// 빈 자리에 꽂기 — 비교문이 돼버려서 아무것도 안 꽂힘
else if(plug[j] == 0){
    plug[j] == item[i];   // ✗ 비교 → plug[]가 영영 0 → ret=0
}
// 미래 계산 — 대입문이 돼버려서 plug[] 오염 + 항상 참
if(plug[j] = item[m]){    // ✗ 대입 → 무조건 진입, 데이터 파괴
```

- 빈 자리 쪽: `plug[j] = item[i]` (대입)
- 미래 비교 쪽: `if(plug[j] == item[m])` (비교)
- 교훈: **"꽂는다"는 대입, "같은지 본다"는 비교.** 한 번에 두 군데를 반대로 틀리면 증상이 얽혀서 원인 찾기가 배로 힘들다.

### 2라운드 — 미래 사용 시점 계산 로직

```cpp
for(int m = n; m < k; m++)   // ✗ m을 구멍 수 n부터 시작
```

- "미래"는 지금 처리 중인 `i`의 **다음**부터. → `m = i + 1`
- 그리고 **첫 번째로 다시 쓰이는 시점**을 찾으면 `break`. 안 그러면 뒤 값으로 덮여서 마지막 등장 시점이 남음.
- 미래에 **아예 안 나오는** 구멍은 `used[j] = INF(999)` → 최우선 제거 대상.

### 3라운드 — `b` 플래그가 너무 일찍 켜짐 (진짜 정답 버그)

```cpp
for(int j = 0; j < n; j++){
    if(plug[j] == item[i]) break;
    else if(plug[j] == 0){ plug[j]=item[i]; break; }
    else b = true;          // ✗ 다른 물건 만나자마자 켜짐
}
```

- `b`("뽑아야 함")를 **첫 mismatch 순간** 켜버림. 그런데 찾는 기기가 **뒤쪽 구멍**에 있을 수 있다.
- 반례: `plug=[3,2]`, `item=2` → `j=0`에서 `b=true`, `j=1`에서 매칭 break. 이미 꽂혀 있는데 `b`가 켜진 채라 removal 분기로 들어가 **멀쩡한 걸 뽑고 `ret++`.**
- 초반엔 왼쪽부터 순서대로 채워져 매칭이 항상 `j=0`이라 안 터지지만, `plug[cnt]`에 새 기기를 넣기 시작하면 순서가 섞여서 매칭이 `j>0`에서 발생 → 그때 터짐.
- **고침**: "루프 도중 아무 때나 켜는 플래그"가 아니라 **"루프를 끝까지 돌았는데 처리 못 했나?"** 하나의 결과값으로. `handled` 플래그를 두고 match/empty에서 `handled=true; break;`, 루프 후 `if(!handled)`일 때만 removal.

## 배운 점

- **오프라인(미래를 다 아는) 문제에서의 최적 교체 = Belady.** "가장 늦게 쓰일 것을 버린다"는 캐시/페이지 교체의 고전 결과. 이 감각을 앞으로 재활용.
- 플래그는 "언제 켜지느냐"가 곧 정의다. `b = true`를 조건 없이 else에 박으면 "부분 관찰"이 "전체 결론"으로 새어나간다. **플래그는 루프가 끝난 뒤에 확정하는 게 안전.**
- `=`/`==` 같은 저수준 오타는 로직이 맞아도 AC를 못 준다. 컴파일 경고(`-Wall`)를 켜면 `if(a = b)`는 잡아줬을 것.

## 개선 여지

- `used[]`를 전역 배열로 매번 재계산하는데, 마지막 기기(`i+1 >= k`) 처리 시 내부 루프가 안 돌아 stale 값이 남을 수 있음(정답엔 영향 없지만 위험). 필요하면 루프 진입 전 `used`를 INF로 초기화.
- `set`/우선순위 자료구조로 "다음 사용 시점"을 관리하면 더 깔끔하지만, N·K가 작아 O(N·K²) 완전 스캔으로도 AC.
