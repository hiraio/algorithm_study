# BOJ 9935 문자열 폭발

- **날짜**: 2026-06-11 (목) — 오늘 2번째 문제 (가용일 목표 2문제 달성)
- **유형**: 스택 (string을 스택으로 사용)
- **결과**: AC (자력, 발상은 맞았고 디버깅으로 완성)

## 문제 핵심
긴 문자열에서 폭탄 문자열이 나타날 때마다 제거. 연쇄 폭발까지 처리 후 남은 문자열 출력(없으면 `FRULA`).

## 핵심 테크닉
- 문자열을 **스택처럼** 한 글자씩 쌓는다.
- 방금 넣은 글자가 **폭탄의 마지막 글자**와 같을 때만 → 스택 끝 m글자가 폭탄과 일치하는지 검사 → 일치하면 끝 m글자 제거.
- 제거 후 남은 스택 top + 이후 글자가 자연스럽게 다시 폭탄을 이룰 수 있어 **연쇄 폭발이 자동 처리**됨.

## 막혔던 포인트 (배운 점)
1. **1차 시도의 결정적 버그**: 비교를 원본 `str`을 스택 크기 인덱스로 했음(`str[s-1-j]`). 폭발이 일어나면 **스택 내용 ≠ str의 앞부분**이라 어긋남. → 반례 `AABB`/`AB`로 확인(정답 FRULA인데 `AB` 출력).
   - 교훈: **비교 대상은 "실제 스택"이어야 한다.** `stack<char>`은 top 아래를 못 보므로 **`string`을 스택으로** 쓰면 인덱스 접근 가능.
2. **`s >= m` 가드** 필요 — 스택이 폭탄보다 짧을 때 음수 인덱스 접근(UB) 방지.
3. **빈 결과 → `FRULA` 출력 분기**를 한 번 빠뜨렸다가 추가.
4. ⚠️ 피해야 할 함정: `string::find`+`erase` 반복 = O(N²) → 글자 100만에서 TLE. 스택 방식이 정답.

## 자기 평가
- 스택으로 문제 푸는 걸 몇 번 반복하니 **풀이 방법이 떠오르기 시작**함 — 유형 체화 중. 발전 체감.
