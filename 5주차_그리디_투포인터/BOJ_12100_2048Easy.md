# BOJ 12100 — 2048 (Easy)

- **날짜**: 2026-07-05 (일)
- **유형**: 완전탐색(DFS 백트래킹) + 시뮬레이션 (격자 이동/병합 + 90도 회전)
- **결과**: 자력 AC

## 핵심 아이디어

최대 5번 이동했을 때 만들 수 있는 가장 큰 블록. 이동 방향은 상·하·좌·우 4가지 → **4^5 완전탐색**.

- 방향마다 이동 함수를 따로 짜지 않고, **"왼쪽으로 밀기" 한 함수 + 판 90도 회전**으로 4방향을 모두 커버.
- 매 깊이에서 4방향을 시도하고, 5번 이동하면 판 최댓값을 갱신.

## 구조 (구조체 캡슐화)

`struct Board`에 판 `a[24][24]`와 메서드 `_move()`, `_rotate90()`, `get_max()`를 묶음.

```cpp
void go(Board c, int here){        // Board를 "값(복사)"으로 받음
    if(here == 5){ c.get_max(); return; }
    for(int i = 0; i < 4; i++){
        c._move();                 // 왼쪽으로 밀기
        go(c, here + 1);           // 복사본이 재귀로 내려감
        c._rotate90();             // 다음 방향을 위해 판 회전
    }
}
```

### 가장 큰 배움 — 값 전달 = 백트래킹 복원이 공짜

- `go(Board c, ...)`가 **판을 통째로 복사**해서 받으므로, 흔한 "상태 저장 → 재귀 → 복원(되돌리기)"을 **한 줄도 안 짜도 됨.** 각 가지가 자기 복사본을 들고 놀다 사라짐.
- 전역 배열이었으면 매 방향마다 `백업 → 이동 → 재귀 → 복구`를 손으로 해야 함 (= 2206·14391에서 반복해 막히던 "상태 되돌리기" 지점).
- 대가는 복사 비용: Board 2304바이트 × 호출 ~1300번 ≈ 3MB 복사 → 4^5 규모에선 전혀 문제없음. **"복사 비용 vs 코드 단순함" 트레이드오프를 의식하고 값 전달을 택한 셈.**
- 교훈 한 줄: **상태를 객체로 캡슐화하면 백트래킹 복원이 공짜가 된다.** 시뮬+완전탐색에서 재사용.

## 90도 회전

```cpp
temp[i][j] = a[n - j - 1][i];   // 시계방향
```

- 반시계는 `temp[i][j] = a[j][n-1-i]`. 이 문제는 4번 돌리면 4방향 다 커버되니 **방향은 무관**.
- 공식 암기보다 "(i,j)에 들어갈 값이 원본 어디서 오나"를 좌표로 유도하는 감이 핵심.

## 이동/병합 로직 — 투 포인터 압축 + 플래그

```cpp
int c = -1, d = 0;                 // c=쓰기 포인터, d=병합 가능 플래그
for(int j = 0; j < n; j++){
    if(a[i][j] == 0) continue;
    if(d && a[i][j] == temp[i][c]) temp[i][c] *= 2, d = 0;   // 합치고 잠금
    else temp[i][++c] = a[i][j], d = 1;                       // 새 칸에 밀어넣기
}
for(c++; c < n; c++) temp[i][c] = 0;
```

- `c` = 지금까지 채운 마지막 위치(쓰기 포인터), `d` = 그 칸이 아직 합쳐질 수 있나.
- **핵심 규칙**: 한 번 합쳐진 칸은 이 턴에 또 안 합쳐짐 → 병합 직후 `d = 0`.
  - `2 2 2 2 → 4 4` (O), `8`이 아님. `2 2 4 → 4 4` (앞 두 개만 병합).
- `temp[i][++c]`로 "새 칸 밀어넣기 + 포인터 전진"을 한 줄에. 이 **"투 포인터로 압축하며 쓰기"** 패턴은 배열 압축/중복 제거에도 그대로 나옴.

## 개선 여지

- `_move`의 `int temp[24][24]`는 `[0..n)` 밖이 미초기화 쓰레기값. `n` 안쪽만 읽어 결과엔 영향 없지만, 습관적으로 초기화 신경 쓸 지점.
