# BOJ 1781 — 컵라면

- **날짜**: 2026-06-12 (금)
- **유형**: 그리디 + 우선순위큐(min-heap), 마감일 스케줄링
- **결과**: 자력 AC (어제 2109 패턴 전이로 수월)

## 핵심 테크닉

마감일까지 단위 작업을 골라 이득(컵라면) 최대화하는 **deadline scheduling**.

1. **마감일 오름차순 정렬**
2. 앞에서부터 컵라면 개수를 **min-heap에 push**
3. push 직후 `pq.size() > 마감일`이면 → **지금까지 고른 것 중 최소 컵라면을 pop** (가장 손해 적은 걸 버림)
4. 마지막에 heap에 남은 것들 합 = 답

정당성: 마감일 `d`까지는 최대 `d`개만 풀 수 있다. 일단 다 담고 용량 초과 시 최소 이득을 버리면, 매 시점 "용량 내에서 이득 최대 집합"이 유지된다. min-heap top이 곧 버릴 후보.

## 2109(순회강연)와의 관계

- **같은 골격**: 마감일 오름차순 + heap에 후보 누적 + 용량 초과 시 조정
- **차이**: 2109는 "보수 최대 보존"(max 관점), 1781은 "컵라면 최대 보존" + 초과분 pop(min-heap)
- 어제 푼 직후라 "하루 1개 / 마감일 / 우선순위큐" 신호를 바로 잡음 → 유형 체화 체감

## 잘한 부분

- `pq.size() > 마감일 ⟺ 마감일 < pq.size()` 조건을 정확히 세움
- push 직후라 초과는 1개씩만 발생 → pop 한 번이면 충분하다는 점까지 맞게 처리

## 다듬을 점 (버그 아님, 인지용)

1. **`!pq.empty()`는 redundant**: 바로 위 `pq.push()` 직후라 항상 비어있지 않음 → 항상 true, 제거 가능. "이 가드가 왜 필요한가" 설명 못 하면 습관적으로 붙인 것.
2. **int vs unsigned 비교**: `v[i].first < pq.size()`에서 `pq.size()`는 size_t. 이번엔 마감일이 항상 양수라 안전하지만, 좌변이 음수가 될 수 있는 문제에선 음수→거대 양수 둔갑으로 터진다. (6/5 15353 `i < a.size()-b.size()` unsigned 재평가 버그와 같은 함정 계열) → 양변 타입 맞추는 습관.

## 배운 점

- 마감일 스케줄링 = "정렬 + min-heap 용량 관리" 한 패턴으로 굳어짐. 2109→1781 연속 풀이로 전이 성공.
