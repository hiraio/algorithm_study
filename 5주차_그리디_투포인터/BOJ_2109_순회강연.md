# BOJ 2109 순회강연

- **날짜**: 2026-06-11 (목)
- **유형**: 그리디 + 우선순위 큐(최대 힙) — 마감일 스케줄링
- **결과**: AC (자력, 단계적 힌트로 발상 교정)

## 문제 핵심
강연 n개. 각 강연은 보수 pᵢ, **마감일 dᵢ 이내**에 해야 받음. 하루에 강연 1개. 총 보수 최대화.

## 핵심 테크닉 — "필터링을 push 타이밍으로 대체"
- 마감일을 **큰 날짜 → 작은 날짜(t)**로 훑는다.
- 날짜 t에 도달하면 **마감 == t인 강연들을 전부 pq에 push** (보수만 담음, `priority_queue<int>` 최대 힙).
- 그러면 현재 pq 안엔 **마감 ≥ t인 것들만** 존재 → `pq.top()`이 자동으로 "오늘 가능한 것 중 최대 보수".
- 하루에 **top 1개만** 꺼내 ret에 더함. **pq는 절대 초기화 안 함** → 못 꺼낸 값은 다음(더 이른) 날짜 후보로 남음.
- 벡터를 매일 다시 뒤지지 않고 **인덱스 포인터 `j`를 앞으로만 전진**시켜 push → 전체 push O(n), 합쳐서 O(n log n + maxD).

## 잘한 부분
- 첫 오접근("같은 날짜끼리 묶고 top 하나만, 날짜 바뀌면 전부 pop")을 **반례(마감2·10, 마감2·8 → 10+8 둘 다 가능)**로 스스로 깨닫고 폐기.
- "pq에 보수만 담고, 마감일은 정렬+포인터에만 쓴다"는 구조 분리를 이해.

## 막혔던 포인트
1. **`pq.top()`으로 조건 필터링이 안 된다**는 점 → "조건 만족하는 것만 pq에 있게 만들면 top이 곧 답"으로 발상 전환 (push 타이밍이 조건을 대신 건다).
2. **"pq 초기화" 오해** — 날짜 바뀌면 비워야 하는 줄 알았으나, 못 꺼낸 값은 **남겨둬야** 더 이른 날짜와 경쟁. 첫 전략의 "다 pop"이 바로 이 실수였음.
3. **"매일 벡터 전체 탐색하면 느리다"는 걱정** → 포인터 `j` 전진으로 O(n) push 해결.
4. 코드 버그: 빈 벡터에 `v[i]` 접근(→ `push_back`/`resize` 필요), 마감/보수를 `.first`/`.second`에 어느 쪽 넣을지 혼동(정렬 기준이 마감이 되려면 마감=`.first`).

## 배운 점
- **그리디 정당성**: 마감일 큰 쪽부터 처리하면 "그 날까지 가능한 후보 전부"가 heap에 모이고, 하루 1개 최대값을 고르는 게 각 날짜의 최적 → 전체 최적. (교환 논증)
- 우선순위 큐는 "조건부 top"을 못 주므로, **컨테이너에 넣는 시점/대상으로 조건을 미리 만족**시키는 패턴.
- 그리디 단골 도구 = 정렬 + 우선순위 큐 (5주차 개념 강의에서 잡은 감과 일치).
