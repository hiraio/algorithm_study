# BOJ 1931 — 회의실 배정

- **날짜**: 2026-06-16 (월)
- **유형**: 그리디 (activity selection, 구간 스케줄링)
- **결과**: 자력 AC (priority_queue 버전)

## 핵심 아이디어

겹치지 않게 최대한 많은 회의를 고르는 문제. 정답 정렬 기준은 **끝나는 시간 오름차순**(같으면 시작 시간 오름차순).

- 정당성: "지금 고르는 회의가 빨리 끝날수록 뒤에 남는 시간이 길어져 더 많은 회의를 넣을 수 있다." 끝 시간 기준 그리디가 최적해를 보장.
- 반례 검증: 시작 빠른 순 / 길이 짧은 순은 반례로 깨지고, **끝 빠른 순만** 안 깨진다.
- 함정: 시작==끝인 길이 0짜리 회의 → 끝 기준 정렬 시 tie면 시작 오름차순으로 풀어야 안전.

## 처음 푼 코드 (priority_queue)

`priority_queue<pair<int,int>, vector<...>, greater<>>`에 `{end, start}`로 넣어 end 오름차순 자동 정렬. 앞에서부터 pop하며 `직전 끝 <= 다음 시작`이면 선택.

- **시간복잡도**: push N + pop N = O(N log N). 점근적으로 최적 → AC.
- **문제점 인지용**:
  1. **PQ는 오버킬**. 회의 집합은 동적으로 변하지 않으니 정렬 한 번이면 끝. PQ는 pop마다 heapify(log N)를 또 내고, 상수 계수·메모리·캐시 효율이 `vector+sort`보다 나쁨. 같은 O(N log N)이라도 "log N 연산 N번"보다 "1번 정렬 + O(1) N번"이 빠름.
  2. **죽은 가지(dead branch)**: `else if(ed==st)`와 `else`의 본문이 완전히 동일 → 한 갈래로 합쳐야 함. `ed==st` 조건은 의도도 불명확(현재 회의 시작==끝).

## 코드 리팩토링 (vector + sort)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n; cin >> n;
    vector<pair<int,int>> v(n);       // {end, start}
    for(auto& [e, s] : v) cin >> s >> e;

    sort(v.begin(), v.end());         // end 오름차순, tie면 start 오름차순

    int ret = 0, last = 0;            // last = 직전 회의 종료시각
    for(auto& [e, s] : v){
        if(s >= last){                // 직전 끝 이후(같아도 OK)에 시작 → 선택
            ret++;
            last = e;
        }
    }
    cout << ret << '\n';
}
```

- `last` 하나만 들고 다니면 됨. PQ도, ed/st 두 변수도, if/else 3갈래도 불필요.
- "겹치면 skip, 안 겹치면 선택"이 `s >= last` 한 줄로 표현됨.

## 배운 점

- **시간복잡도가 최적이어도 자료구조 선택은 별개**. "동적 갱신이 없는데 PQ를 쓰면 상수 손해" — 정적 데이터엔 sort 한 방.
- 그리디 정렬 기준은 "반례로 후보를 깨보는" 방식으로 검증 → 끝 시간 기준만 생존.
- 1781·2109(마감일 스케줄링, heap 필요)와 대비: 1931은 heap이 필요 없는 정렬 그리디. "heap이 진짜 필요한가"를 구분하는 감각.
