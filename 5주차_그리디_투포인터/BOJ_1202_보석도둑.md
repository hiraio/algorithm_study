# BOJ 1202 — 보석 도둑

- **날짜**: 2026-06-16 (월)
- **유형**: 그리디 + 우선순위큐(max-heap) + 투포인터, 정렬 매칭
- **결과**: 자력 AC (힌트로 개념 잡고 코드는 직접 디버깅)

## 문제 핵심

보석 N개(무게 m, 가격 v), 가방 K개(용량 c). **가방 하나엔 보석 하나**, 무게 ≤ 용량. 가격 합 최대화. N·K ≤ 30만.

## 왜 naive가 안 되나 (스스로 의심한 부분)

처음 발상: "보석 가격 내림차순 + 가방 크기 오름차순, 보석마다 들어갈 가방을 스캔." → 최악 O(N·K) = 9×10¹⁰ → TLE. **이 직감(가방 일일이 스캔하면 느림)이 맞았음.**

## 정답 골격: 가방 기준으로 뒤집기 + 누적 힙

- 보석·가방 **둘 다 크기(무게/용량) 오름차순 정렬**
- 가방을 작은 것부터 보며, **무게 ≤ 현재 용량인 보석을 전부 max-heap에 push** (포인터는 앞으로만 → 보석은 평생 1번씩만 push)
- 가방마다 heap top 1개 pop → 가격 누적
- 복잡도: push N + pop K = **O((N+K) log N)**

```cpp
sort(bag);            // 용량 오름차순
sort(vosuk);          // {무게, 가격} → 무게 오름차순
priority_queue<int> pq;   // 가격 max-heap, 단 하나
int point = 0; long long ret = 0;

for(int c : bag){
    while(point < (int)vosuk.size() && c >= vosuk[point].first){
        pq.push(vosuk[point].second);   // 후보 등록
        point++;
    }
    if(!pq.empty()){ ret += pq.top(); pq.pop(); }  // 한 개만 적재
}
```

## 막혔던 개념 (질문으로 정리한 것들)

이 문제의 진짜 난관은 코드가 아니라 **개념 4단 오해**였고, 하나씩 풀어가며 AC:

1. **"가방마다 보석을 또 스캔하면 보석도 재스캔 아니냐"** → 보석 무게 오름차순 + **포인터 앞으로만** 전진. 각 보석은 배열에서 딱 1번 꺼내져 heap으로 감. 재스캔 없음.
2. **"무게 ≤ c 최댓값들을 다 더하면?"** → ❌. 가방엔 하나만. pop은 **가방당 1번**.
3. **"가방 개수만큼 pq를 만들어야?"** → ❌. **힙은 단 하나.** 안 가져간 보석이 힙에 남아 다음(더 큰) 가방의 후보로 누적되는 게 핵심. 가방마다 새로 만들면 누적이 깨져 틀림.
4. **"힙에 여러 개 push = 한 가방에 여러 개 넣기 아니냐"** → ❌. **힙 = 후보 대기실 ≠ 가방.** push는 "입장 자격 등록", pop이 "실제 적재". 대기 줄에서 한 명만 입장, 나머지는 남아서 다음 가방 기다림.

## 처음 코드의 버그 4개 (직접 수정)

1. **`pq`를 for 루프 안에서 선언** → 가방마다 새 힙 = 누적 파괴. (오해 3의 코드판) → 루프 바깥으로.
2. **`while(b){ ... break; }`** 의 무조건 break → 가방당 보석 1개만 push. → 평범한 `while(조건1 && 조건2)`로 교체, `b`·`break` 제거.
3. **`ret`이 int** → 가격 합 오버플로 → `long long`.
4. **빈 힙 `pq.top()` + `pop()` 누락** → UB & 같은 보석 재적재 → `if(!pq.empty()){ top; pop; }`.

## 정당성 (그리디가 최적인 이유)

가방을 작은 것부터 처리하면, 각 가방 차례엔 "그 가방에 들어갈 수 있는 모든 보석"이 힙에 모여 있다. 그중 최댓값을 집는 게 손해가 아닌 이유: 더 큰 가방은 이 보석도 어차피 담을 수 있으니, **작은 가방에 가장 비싼 후보를 양보해도 큰 가방이 손해 보지 않는다**(교환 논증). 남은 보석은 더 큰 가방들이 이어받음.

## 다듬을 점 (인지용)

- `point < vosuk.size()`에서 point=int, size()=size_t(unsigned). point는 항상 ≥0이라 이번엔 안전하지만, 1781·15353에서 데인 int vs unsigned 함정 계열 → `(int)vosuk.size()` 캐스팅 습관.

## 배운 점

- **"전체를 스캔"하는 naive를 "정렬 + 단방향 포인터 + 누적 자료구조"로 바꾸면 O(N·K) → O((N+K)log N).** 1781/2109(마감일 스케줄링)와 같은 골격: 정렬해두고 heap에 후보 쌓아 관리.
- 헷갈릴 땐 "힙은 가방이 아니라 후보 대기실" 한 줄로 정리되더라.
