# BOJ 14620 — 꽃길 (백트래킹 + 함수 분리 idiom)

**날짜**: 2026-04-08  
**유형**: 백트래킹 + 함수 분리

## 잘한 부분
- BFS는 visited를 공유 못 한다는 점에서 백트래킹으로 전환을 스스로 판단
- canPlant/plant/unplant 세 함수로 분리한 구조도 직접 도출
- 시작 위치 매개변수가 "중복 조합 회피"를 위함이란 것도 스스로 답함

## 막혔던 포인트
- 한 함수 안에서 4칸 표시 도중 실패하면 부분 복원하는 방식 시도 → 시점 너무 헷갈림
- canPlant/plant/unplant에서 중심 (y,x)를 빼먹음 (4방향만 처리)
- `int y = start/N` → 루프 변수 `i`로 안 바꿔서 (y,x)가 계속 첫 위치로 고정
- `sum += cost` 지역변수 누적 → 형제 호출 사이에 sum 오염
- 입력 받을 때 `j < N` 대신 `i < N` 오타

## 배운 점
1. **백트래킹 함수 분리 idiom (can/do/undo)**: canPlant(부작용 없는 검사) → plant(변경) → unplant(복원). "부분 변경 후 복원" 시나리오가 아예 사라짐
2. **두 종류의 "되돌릴 거리" 구분**: 공유 자료구조(used[][])는 명시적 unplant로 복원, 누적 값(sum)은 매개변수로 `sum + cost` 넘기기. 지역변수에 직접 누적하면 형제 호출 사이로 새어나감
3. **2D 좌표 → 1D 인덱스 변환**: `for(p = start; p < N*N; p++)` + `y = p/N, x = p%N`. 격자 백트래킹에서 "다음 위치부터" 처리할 때 1D 변환이 가장 깔끔

## 느낀 점
- "백트래킹 재귀 함수 구현이 신기하고 재밌다" — 패턴이 손에 잡히기 시작한 신호

## 복습 (2026-05-15)
- can/do/undo 구조 기억하고 직접 작성
- **재발한 실수**: 루프 변수 `i` 안 넘기는 실수, 1D→2D 변환 시 N 대신 N-1로 나누는 실수
