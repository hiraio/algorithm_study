# BOJ 15684 — 사다리 조작 (시뮬레이션 + 백트래킹)

**날짜**: 2026-04-09  
**유형**: 시뮬레이션 + 백트래킹

## 핵심 테크닉
- 답 상한이 3으로 작음 → k=0,1,2,3 순회 백트래킹
- `board[r][c]=1`은 "c번과 c+1번 연결"로 정의(c: 1~n-1)
- check는 각 열에서 출발해 행마다 좌/우 조건부 이동
- 2D→1D 인덱스로 중복 조합 회피
- 가지치기 `cnt>=answer` 필수

## 잘한 부분
- "조합으로 0/1/2/3개 시도" 아이디어 스스로 도출
- `check / draw / undraw / go` 4함수 구조를 힌트 없이 설계
- 2D→1D 인덱스 변환 직접 시도
- "시간 오래 걸릴 것 같다"는 감도 맞음

## 막혔던 포인트
- 사다리타기 → 백트래킹 연결이 쉽지 않았음. "최적화 문제"로 포장돼 있어 DP/그리디 의심 → 답 상한이 3으로 작다는 점이 백트래킹 단서
- 문제 규칙을 배열로 모델링이 한 겹 더 어려움: "가로선 = 두 세로선 사이 공간"
- 이동 규칙이 4방향도 앞뒤도 아님 — "행은 무조건 내려가고, 가로선 유무에 따라 조건부로 좌/우 한 칸"
- check에서 "왼쪽 이동은 `board[r][x-1]`, 오른쪽 이동은 `board[r][x]`" 비대칭 접근
- 열 범위가 n이 아닌 n-1인 이유를 "최적화"로 오해 → 정의에서 자동 파생
- **인덱스 순서 불일치 재발**: main에서 `board[행][열]`, check에서 `board[열][행]`으로 읽음
- **for 루프 변수 실수 재발**: `int y = idx / n`에서 `idx`가 아닌 `i`를 써야 함
- check 종료조건 반대 (`==`와 `!=` 혼동)
- 내부 루프 상한 `m`(가로선 개수)과 `h`(높이) 혼동
- "인접 가로선 금지" 조건 누락
- 답 저장 전역 변수 없이 그냥 return

## 배운 점
1. **답 상한이 작은(≤10) 최적화 문제 = 백트래킹 신호**
2. **문제의 자연어 → 자료구조 정의는 별도의 사고 단계**. 정의부터 확정하고 코드로 내려가야 함
3. **2D→1D 인덱스 변환 공식**: `idx = r*W + c`, `r = idx/W`, `c = idx%W`. W는 "한 행의 가로 길이"
4. **백트래킹 가지치기 필수**: `if(cnt >= answer) return`
5. **check 함수는 부작용 없는 검사만, go는 상태 변경과 탐색만** — 역할 분리가 명확할수록 디버깅이 쉬움

## 반복된 실수 (주의 필요)
- **배열 인덱스 순서 불일치**: 14620에서도, 15684에서도 나옴 → `// board[행][열] = 의미` 강제
- **for 루프 변수 vs 함수 파라미터 혼동**: 14620의 `start/i`, 15684의 `idx/i` 버그가 완전 동일

## 느낀 점
- 3주차 최종 보스 체감. 14620·1189에서 배운 백트래킹 뼈대 + 2D→1D 변환 + 시뮬레이션이 복합 문제로 통합되는 경험

## 복습 (2026-05-15)

- **재발한 실수**: 행열 뒤집힘(board[here][j] vs board[j][here]), 인접 가로선 금지 조건 누락, 가지치기 위치 잘못 배치, 루프 변수 실수(네 번째)
