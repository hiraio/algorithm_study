# BOJ 14391 — 종이 조각 (각 칸 가로/세로 2상태 → 비트마스킹 완전탐색)

**날짜**: 2026-06-02
**유형**: 비트마스킹 / 완전탐색 (각 칸을 2가지 상태로 분류)

## 핵심 통찰
- 처음엔 "큰 숫자부터 직사각형으로 잘라내는 그리디 + 분할"로 접근하려 함 → **틀린 방향**
  - 한 조각의 값은 **자릿수(place value)** 에 좌우됨. 큰 숫자 하나 살리려다 나머지가 손해 볼 수 있음
  - 모든 칸을 빠짐없이 덮는 **분할** 문제라 국소 그리디로 전역 최적 보장 안 됨
- **발상 전환**: "어디를 자를까"가 아니라 **각 칸이 어떤 상태인가**로 본다
  - 각 칸 = *가로로 읽히는 수의 일부* 또는 *세로로 읽히는 수의 일부* → **2가지 상태**
  - N, M ≤ 4 → 칸 ≤ 16개. 2상태 × 16칸 = `2^16` → **전체 배치 완전탐색 가능**
- 따라서 재귀/그리디 없이 `for mask = 0 .. (1<<(N*M))-1` 단순 반복으로 모든 배치를 다 돌린다

## 한 mask의 점수 계산
- **가로 수**: 각 행을 왼→오로 훑으며 가로 비트면 `curr = curr*10 + 숫자`, 세로 비트(끊김)면 `합 += curr; curr = 0`. 행 끝에서 flush.
- **세로 수**: 각 열을 위→아래로 똑같이. 비트 조건만 반대.
- `curr*10 + digit` 누적이라 **자릿수/pow 계산 불필요** (왼쪽부터 읽으면 자릿수 자동).

## 막혔던 포인트 (반복 실수 모음)
1. **루프 변수 vs 인덱스 혼동** — `for(k...)` 도는데 본문은 `index`만 써서 index가 영원히 0. [[project_15684_insight]]에서 정리한 그 실수 재발.
2. **flush 위치** — `합 += curr`를 안쪽 루프 *안*에 둬서 매 칸 중복 합산. flush는 **루프 밖(행/열 끝)** 에서 한 번.
3. **curr 리셋 시점** — 가로 수가 행을 넘어 이어지면 안 됨 → `curr = 0`을 **각 행/열 시작**에서.
4. **`^`는 거듭제곱 아님** — C++에서 `10^pos`는 XOR. `curr*10+digit`로 우회.
5. **연산자 우선순위** — `i & (1<<idx) == 0`은 `==`가 먼저 묶여서 항상 false. `(i & (1<<idx)) == 0` 또는 `(i>>idx & 1)==0`.
6. **idx 곱셈 수는 항상 m** — 비트 인덱스 = `행*m + 열` (m=열 개수). 가로/세로 무관하게 동일. n으로 바꾸면 같은 칸이 다른 비트를 가리켜 버그.

## 가로/세로 인덱싱 정리 (항상 헷갈리는 부분)
변수 이름(j, k)이 가로/세로에서 역할이 바뀌어도 **공식 `행*m+열`은 안 바뀐다**:

| 검사 | 바깥 j | 안쪽 k | 행 | 열 | idx | board |
|------|--------|--------|-----|-----|------|-------|
| 가로 | 행 고르기 | 열 훑기 | j | k | `j*m+k` | `board[j][k]` |
| 세로 | 열 고르기 | 행 훑기 | k | j | `k*m+j` | `board[k][j]` |

- 가로: 바깥 루프가 "어느 행"을 고름 → j=행
- 세로: 바깥 루프가 "어느 열"을 고름 → j=열
- **팁**: j,k 대신 `r`(row)/`c`(col)로 이름 붙이면 idx를 항상 `r*m+c`로 통일해 실수 예방.

## 정답 코드
```cpp
#include<bits/stdc++.h>
using namespace std;
const int max_n = 4;
int n, m, board[max_n][max_n], idx, ret; // n=세로, m=가로, 비트 1=가로 0=세로
string str;
int main(){
    ios_base::sync_with_stdio(false);
    cin.tie(NULL); cout.tie(NULL);
    cin >> n >> m;
    for(int i = 0; i < n; i++){
        cin >> str;
        for(int j = 0; j < m; j++) board[i][j] = str[j] - '0';
    }
    for(int i = 0; i < (1 << (n * m)); i++){
        int tempRet = 0;
        // 가로: 행 고정(j), 열 훑기(k)
        for(int j = 0; j < n; j++){
            int curr = 0;
            for(int k = 0; k < m; k++){
                idx = j * m + k;
                if(i & (1 << idx)) curr = curr * 10 + board[j][k]; // 1=가로
                else { tempRet += curr; curr = 0; }
            }
            tempRet += curr;            // 행 끝 flush
        }
        // 세로: 열 고정(j), 행 훑기(k)
        for(int j = 0; j < m; j++){
            int curr = 0;
            for(int k = 0; k < n; k++){
                idx = k * m + j;
                if((i & (1 << idx)) == 0) curr = curr * 10 + board[k][j]; // 0=세로
                else { tempRet += curr; curr = 0; }
            }
            tempRet += curr;            // 열 끝 flush
        }
        ret = max(ret, tempRet);
    }
    cout << ret << '\n';
    return 0;
}
```

## 배운 점
1. **문제를 "상태값"으로 분해하는 시각** — 그리디/구현으로 달려들기 전에 "이 문제가 어떤 상태를 가지는가, 상태가 2가지면 비트마스킹 완전탐색이 되나?"를 먼저 묻는다. [[project_19942_insight]] 부분집합 전탐색과 같은 계열.
2. **가로/세로 인덱싱 + 초기화/합산 시점**은 늘 헷갈린다 → flush는 루프 밖, 리셋은 행/열 시작, idx 곱셈은 항상 m. 표로 정리해 체화.
