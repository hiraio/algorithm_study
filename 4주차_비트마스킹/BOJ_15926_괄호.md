# BOJ 15926 — 가장 긴 올바른 괄호 부분 문자열

- **날짜**: 2026-06-09 (AC). 6/6 개념·수도코드 → 6/9 완주
- **유형**: 스택 (괄호 매칭 + 인덱스 저장). 3015과 같은 모노토닉/인덱스 스택 계열
- 주어진 괄호 문자열에서 **올바른 괄호인 연속 부분 문자열의 최대 길이** (n ≤ 200,000 → O(n))

## 문제 핵심
- 부분 문자열은 **연속 구간**이라 후보가 2^n이 아니라 O(n²). 그래도 n=20만이면 O(n²) TLE → O(n) 스택.
- 올바른 구간은 항상 "어떤 **벽** 바로 다음 칸"부터 시작 → **벽의 위치만 알면 길이 = i − 벽위치**.

## 핵심 테크닉
스택에 **인덱스**를 담고, 시작 시 **`-1`**(가상의 벽)을 미리 push.

```
for i in 0..n-1:
    if s[i]=='(': push i
    else:                       // ')'
        pop
        if stack.empty(): push i        // 짝 없는 ')' → 새 벽
        else: ret = max(ret, i - stack.top())
```

- 스택 맨 밑에 깔린 값(`-1` 또는 짝 없는 `)`의 인덱스) = **"여기까진 못 쓴다"는 벽**.
- 두 종류 벽: ① 안 닫힌 `(` 는 pop 안 되고 남아 자연히 벽 ② 짝 없는 `)`는 pop 후 empty가 되는 순간 그 인덱스를 새 벽으로 push.
- `-1`을 미리 깔아야 첫 구간도 `i-(-1)` 공식이 안 깨짐.

## 잘한 부분
- "벽 다음부터 현재까지가 올바른 구간" 직관을 잡고, `i - top`으로 길이 계산
- `-1` base 처리, empty 분기까지 정확히 구현 → 한 번에 AC

## 막혔던 포인트
- **스택을 써야 하는지 자체를 몰랐음.** 처음엔 "각 칸을 조건 분기하면?" → 2^n 걱정 → deque 떠올림 정도에서 멈춤.
- **`top`과 인덱스로 "어느 시점에 무슨 행동을 하는가"** 그 조건문(언제 push, 언제 pop, pop 후 무엇)을 잡는 데 시간을 많이 씀.
- 초반 카운터(`cnt`) 방식은 안 닫힌 `(`가 앞뒤 구간을 끊는 걸 처리 못 함 (반례 `()(()` → cnt 방식은 4, 정답 2).

## 배운 점
- 모노토닉/인덱스 스택의 그림: **스택에 "아직 결판 안 난 후보(=벽)"만 남기고, 매칭되는 순간 길이를 잰다.** 3015과 동일한 사고.
- "통(스택)에 무엇을 담아야 미래 판단이 되는가" → 여기선 **인덱스(벽 위치)**. 3015에선 (키,개수). 매번 이 질문부터.
- 빈 스택 분기(`empty()`)가 곧 "짝 없는 괄호" 신호. 이게 없으면 음수 길이로 터짐.

## 최종 AC 코드
```cpp
#include<bits/stdc++.h>
using namespace std;
int n, ret;
string str;
stack<int> st;
int main(){
    ios_base::sync_with_stdio(false);
    cin.tie(NULL); cout.tie(NULL);
    cin >> n >> str;
    st.push(-1);
    for(int i = 0; i < n; i++){
        if(str[i] == '(') st.push(i);
        else{
            st.pop();
            if(st.empty()) st.push(i);          // 짝 없는 ')' → 새 벽
            else ret = max(ret, i - st.top());  // 벽 다음부터 i까지 길이
        }
    }
    cout << ret << '\n';
    return 0;
}
```
