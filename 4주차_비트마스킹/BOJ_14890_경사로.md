# BOJ 14890 — 경사로

**날짜**: 2026-05-28
**유형**: 시뮬레이션 / 구현 (비트마스킹 아님 — 4주차 커리큘럼 안에 들어있지만 비트마스킹 문제는 아니다)
**난이도 체감**: 접근은 떠올랐는데 코드량이 많아서 강의 풀이와의 격차가 컸음

## 문제 요약
- N×N 격자, 각 칸에 높이. 한 줄(행 또는 열)을 끝까지 지나갈 수 있는 길의 개수.
- 인접 칸 높이차 1이면 길이 L짜리 경사로를 놓을 수 있음. 경사로는 낮은 쪽에 L칸이 같은 높이로 연속해야 놓을 수 있고, 같은 칸에 두 번 놓을 수 없음.

## 1차 접근 (내 풀이 — iscross 마킹)

### 접근법
- "인접 차이 1을 발견하면 그 자리에서 검사한다"는 시뮬레이션 정공법
- 오르막(`cur < nxt`): 현재 위치에서 **왼쪽으로 L칸**이 모두 `cur`인지 + 그 칸들이 아직 안 쓰였는지
- 내리막(`cur > nxt`): 다음 위치에서 **오른쪽으로 L칸**이 모두 `nxt`인지 + 그 칸들이 아직 안 쓰였는지
- 같은 칸에 경사로 두 번 못 놓으니까 `used[]` 배열로 마킹
- 행/열 각각 별도 함수로 검사

### 코드
```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAX_N = 100;
int n, L;
int board[MAX_N][MAX_N];

bool checkRow(int row) {
    vector<bool> used(n, false);
    for (int j = 0; j < n - 1; j++) {
        int cur = board[row][j], nxt = board[row][j + 1];
        if (cur == nxt) continue;
        if (abs(cur - nxt) != 1) return false;
        if (cur < nxt) {
            for (int k = 0; k < L; k++) {
                int x = j - k;
                if (x < 0 || board[row][x] != cur || used[x]) return false;
            }
            for (int k = 0; k < L; k++) used[j - k] = true;
        } else {
            for (int k = 0; k < L; k++) {
                int x = j + 1 + k;
                if (x >= n || board[row][x] != nxt || used[x]) return false;
            }
            for (int k = 0; k < L; k++) used[j + 1 + k] = true;
        }
    }
    return true;
}

bool checkCol(int col) {
    vector<bool> used(n, false);
    for (int i = 0; i < n - 1; i++) {
        int cur = board[i][col], nxt = board[i + 1][col];
        if (cur == nxt) continue;
        if (abs(cur - nxt) != 1) return false;
        if (cur < nxt) {
            for (int k = 0; k < L; k++) {
                int y = i - k;
                if (y < 0 || board[y][col] != cur || used[y]) return false;
            }
            for (int k = 0; k < L; k++) used[i - k] = true;
        } else {
            for (int k = 0; k < L; k++) {
                int y = i + 1 + k;
                if (y >= n || board[y][col] != nxt || used[y]) return false;
            }
            for (int k = 0; k < L; k++) used[i + 1 + k] = true;
        }
    }
    return true;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);
    cin >> n >> L;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) cin >> board[i][j];
    int ans = 0;
    for (int i = 0; i < n; i++) {
        if (checkRow(i)) ans++;
        if (checkCol(i)) ans++;
    }
    cout << ans << '\n';
    return 0;
}
```

### 막혔던 포인트
1. **함수 시그니처 헷갈림** — 처음에 `prevcheck(y, x, prev)` 한 함수만 만들어놓고 행 탐색에 갖다 썼는데, 열 탐색까지 같은 함수로 처리하려니 (y, x) 어느 쪽이 고정인지 헷갈렸음. 결국 행/열 분리.
2. **iscross 마킹 누락 위험** — 처음 짠 코드에선 "L칸이 다 같은 값인가"만 봤음. `2 1 1 2`(L=2) 같이 내리막 + 오르막이 인접한 케이스에서 두 경사로가 같은 칸을 공유하려 드는 함정을 놓침 → AI가 짚어줘서 추가.
3. **`ret` 카운팅 위치** — break 후 ret 그대로 두고 다음 행으로 가는 흐름이 어색했음. `checkRow(i)`가 bool 리턴하고 main에서 합산하는 게 훨씬 깔끔.

## 2차 접근 (강의 풀이 — 런 길이 카운터)

### 접근법
- 같은 값이 몇 칸 연속됐는지 `cnt` 하나에 누적
- 오르막(`+1`) 만나면 "직전 같은 값이 L개 이상 쌓였나" 검증 (`cnt >= L`) → 새 높이에서 `cnt = 1`로 리셋
- 내리막(`-1`) 만나면 "앞으로 L칸이 같은 값이어야 한다"를 예약 → `cnt = -L + 1`로 세팅, 같은 값마다 +1되어 0에 도달하면 완성
- 음수 cnt = "내리막 경사로 진행 중, 아직 미완성"
- 끝까지 가서 `cnt >= 0`이면 통과 (마지막 내리막 경사로까지 완성된 상태)
- **전치 행렬 트릭**: 입력 시 `a[i][j] = m; b[j][i] = m;` 으로 동시에 만들어서 같은 함수를 두 번 호출

### 코드
```cpp
#include <bits/stdc++.h>
using namespace std;

int n, m, l, a[104][104], b[104][104], ret;

void solve(int a[104][104]) {
    for (int i = 0; i < n; i++) {
        int cnt = 1;
        int j;
        for (j = 0; j < n - 1; j++) {
            if (a[i][j] == a[i][j + 1]) cnt++;
            else if (a[i][j] + 1 == a[i][j + 1] && cnt >= l) cnt = 1;
            else if (a[i][j] - 1 == a[i][j + 1] && cnt >= 0) cnt = -l + 1;
            else break;
        }
        if (j == n - 1 && cnt >= 0) ret++;
    }
}

int main() {
    cin >> n >> l;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            cin >> m;
            a[i][j] = m;
            b[j][i] = m;
        }
    }
    solve(a); solve(b);
    cout << ret << '\n';
    return 0;
}
```

### 핵심 트릭 이해
- **`cnt` 부호로 오르막/내리막 상태 인코딩**: 양수 = "지금까지 N칸 같은 값", 음수 = "내리막 경사로 진행 중, 앞으로 (-cnt+1)개 더 필요". 마킹 배열이 필요 없는 이유 — 카운터 상태에 "현재 경사로 진행 중인지"가 들어 있음.
- **내리막 조건의 `cnt >= 0`**: "직전 내리막이 완성됐어야 새 내리막 시작 가능". 미완성(`cnt < 0`)인데 또 내리막이 오면 즉시 fail.
- **마지막 체크 `j == n-1 && cnt >= 0`**: 마지막 내리막 경사로가 완성 안 된 채로 줄이 끝나면 통과 아님.
- **전치 행렬**: N×N 정사각에서 행/열 양쪽을 같은 함수로 돌리는 idiom. 다른 시뮬레이션 문제에서도 재활용 가능.

## 두 풀이 비교

| 항목 | 내 풀이 (iscross) | 강의 풀이 (런 길이 cnt) |
|------|-------------------|------------------------|
| 발상 | 차이 발견 → 해당 방향 L칸 검사 → 마킹 | 같은 값 런 길이 누적 → 차이 시점에 검증 |
| 마킹 배열 | `used[]` 필요 | 불필요 (카운터 상태에 인코딩) |
| 행/열 처리 | 함수 두 개 분리 | 전치 행렬 + 함수 하나 재호출 |
| 코드량 | 약 50줄 (함수 분리) | 약 25줄 |
| 시간복잡도 | O(N²) | O(N²) |
| 디버깅 난이도 | 의도 명시적이라 쉬움 | `cnt = -L + 1`의 의미 이해 필요 |
| 가독성 | 한눈에 의도 파악 | 트릭 알면 짧고 우아 |

**성능은 동급.** 두 풀이 다 한 칸당 상수 횟수만 본다.

## 배운 점
1. **런 길이 카운터 패턴** — 시뮬레이션 문제에서 "한 줄 따라가면서 상태 추적"이 필요할 때, 마킹 배열 대신 단일 카운터로 압축할 수 있다는 발상. 부호로 두 가지 상태를 분리하는 트릭이 핵심.
2. **전치 행렬 idiom** — 정사각 격자에서 행/열 양쪽을 같은 로직으로 돌릴 때, 입력 시점에 `b[j][i] = m`으로 미리 전치해두면 같은 함수 두 번 호출로 끝남. 다른 격자 시뮬레이션 문제에도 적용 가능.
3. **"무식한 풀이가 틀린 풀이는 아니다"** — iscross 마킹 방식도 정답으로 가는 정공법이고 O(N²)로 효율도 같다. 짧은 코드 = 더 나은 코드가 아니라 "다른 패턴을 알고 있는 코드"일 뿐. 패턴 라이브러리에 하나 추가했다고 받아들이는 게 맞다.
4. **첫 접근에서 빠뜨렸던 경계 조건** — "L칸 같은 값인가" 외에 "이미 경사로 놓인 칸인가"를 같이 봐야 한다는 점은 `2 1 1 2`(L=2) 같은 케이스를 머리로 돌려봐야 보임. 시뮬레이션 문제에서 "두 사건이 인접해서 자원을 공유하려 할 때" 체크 빠뜨리기 쉬움.

## 코드 리팩토링 (강의 풀이 기준)
- iscross 배열 제거 → cnt 한 변수로 통합
- 행/열 분리 함수 두 개 → 전치 행렬 + 함수 하나
- 약 50줄 → 약 25줄로 축약
