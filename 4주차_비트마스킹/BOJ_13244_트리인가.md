# BOJ 13244 — Tree? (트리 판정)

**날짜**: 2026-06-04
**유형**: 그래프 / DFS 연결성 판정
**(주의: 4주차 Day5 문제지만 비트마스킹 아님 — 그래프 기초)**

## 핵심 아이디어
무방향 그래프가 트리인지 판정. 트리의 정의 3조건 중 **두 개만** 검사하면 된다.
1. **간선 수 == 정점 수 - 1** (`m == n-1`)
2. **연결되어 있는가** (DFS 한 번 → 전부 방문됐는지)

> 핵심: "간선 n-1개 + 연결"이면 **사이클은 자동으로 없다.** 그래서 사이클 검사 따로 불필요.

## 잘한 부분
- 트리를 "edge 제거해도 연결되나" 같은 복잡한 발상 대신 **간선 수 + 연결성** 두 조건으로 환원
- DFS로 연결성 판정 (인접 리스트 `vector<int> adj[]`)
- 테스트케이스마다 `adj.clear()` + `memset(visited)` 초기화 챙김

## 막혔던 포인트
- **댕글링 if/continue**: `if(t-1!=m) cout<<"graph"; continue;` — 중괄호 없어서 `continue`가 **매번 무조건** 실행 → 모든 케이스가 검사 전에 스킵됨. `{ ... }`로 묶어 해결
- **출력 루프에서 다중 출력**: 방문된 정점마다 `"tree"`를 찍어 한 케이스에 여러 줄 나옴. → flag 하나로 "안 방문된 정점 있나" 먼저 다 훑고 **루프 끝나고 한 번만** 출력 (2206에서 `ret` 하나로 모으던 패턴과 동일)
- 배열 크기 `max_n` 제약 확인 (정점 상한 < 배열 크기인지)

## 배운 점
- 트리 판정 = `m==n-1` && `연결` 두 조건. 사이클은 따로 안 본다
- `if`에 문장 2개 묶으려면 **반드시 중괄호** — 한 줄 `if` + `;`은 버그의 온상
- "여러 후보 중 답 하나만 출력" → 루프 안에서 즉시 출력 말고 **flag로 판정 후 1회 출력**
