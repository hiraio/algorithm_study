# BOJ 15353 — 큰 수 A+B (2)

- **날짜**: 2026-06-05
- **유형**: 문자열 / 큰 수(다중 정밀도) 덧셈
- **결과**: AC

## 핵심 테크닉
- 수가 최대 10000자리 → `long long`(최대 `9223372036854775807`)으로도 표현 불가 → **문자열로 받아 손으로 더하듯 자리별 계산**.
- 일의 자리부터 더하려고 두 문자열을 **reverse** → 인덱스 0 = 일의 자리.
- 길이가 다르면 짧은 쪽 **앞에 0 패딩**해서 자리 맞춤.
- 자리올림(carry) 정석 idiom:
  ```cpp
  int r = (a[i]-'0') + (b[i]-'0') + up;
  up = r / 10;            // 윗자리로 넘길 값
  ret += (r % 10 + '0');  // 이번 자리 숫자 → 문자
  if(up) ret += '1';      // 루프 후 마지막 carry (9999+1=10000)
  ```
- 결과는 거꾸로 쌓였으니 출력 전 다시 reverse.

## 막혔던 포인트
1. **패딩 루프의 unsigned 재평가 버그 (핵심)**
   ```cpp
   for(int i=0; i < str1.size() - str2.size(); i++) str2 = '0' + str2;
   ```
   조건의 `str2.size()`가 **매 반복마다 다시 계산**되는데, 패딩으로 str2가 길어지면서 차이가 줄어 **0을 한 개만 붙이고 일찍 멈춤**. 그 뒤 길이가 모자란 채로 `str2[i]` 범위 밖 접근 → `'\0'`(ASCII 0)을 읽어 `0-'0' = -48` → `r`이 음수 → `r%10`도 음수 → `+'0'` 하면 `'('`,`')'` 같은 엉뚱한 기호가 출력됨. **길이가 다른 입력(999+1 등)에서만 터져서** 발견이 늦었음.
   - 해결: **차이를 루프 전에 변수로 고정** (`int diff = str1.size()-str2.size();`) 하거나 `while(짧은쪽 < 긴쪽)`로.
2. `string += int`는 그 정수를 **ASCII 문자**로 붙임 → 숫자엔 반드시 `+ '0'`. 빠뜨리면 괄호/제어문자로 깨짐. (`'7'-'0'`의 반대)
3. 초기 버전: 패딩 결과를 `str2`에 다시 담지 않고 버림(`'0'+str2;`), `if(i = s-1)`(대입/비교 혼동) 등.

## 배운 점 (오늘의 큰 깨달음)
- **"인간처럼 케이스를 나누는 사고" → "컴퓨터로 간소화하는 사고"로의 전환.**
  내가 짠 `if(carry?) / if(10넘음?) / if(마지막?)` 2×2×2 분기가 **단 네 줄**로 압축됨.
- **정해진 패턴**:
  - "~이상이면 빼고 윗자리로 넘긴다" → `/`(몫=넘길 값), `%`(나머지=남길 값). carry·시계(60→1시간)·진법변환 다 같은 꼴.
  - "있을 때만 더한다" → 없을 때 0으로 두고 **항상 더하기** (carry를 항상 `+up`).
  - "첫/마지막만 특별 처리" → 가능하면 루프 **밖**으로.
- 케이스를 다 떠올린 건 문제를 정확히 이해했다는 증거. 다음 단계는 "이 분기들을 묶는 연산이 있나?"를 묻는 습관.
