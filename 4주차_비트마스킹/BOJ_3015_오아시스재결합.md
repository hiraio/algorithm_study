# BOJ 3015 — 오아시스 재결합

- **날짜**: 2026-06-09 (AC). 6/6에 시도 → 막힘 → 강의 시청 → 6/9 재구현으로 완주
- **유형**: 모노토닉 스택 (monotonic stack, 단조 감소 스택) — *비트마스킹 아님*
- **난이도 체감**: 높음. "스택에 무엇을 담는가"가 핵심이라 직관이 늦게 잡힘

## 문제 핵심
일렬로 선 사람들 중, 두 사람이 **서로 볼 수 있는 쌍의 개수**를 센다.
- 두 사람 i, j가 보이는 조건: **사이에 있는 모든 사람의 키 ≤ min(키i, 키j)** (= 더 작은 쪽보다 큰 사람이 사이에 없음)
- n ≤ 500,000 → O(n²) 완전탐색은 **약 1.25×10¹¹ → TLE**. O(n) 모노토닉 스택 필요.

## 핵심 테크닉
스택에 **(키, 그 키가 연속으로 몇 명인지 개수)** 쌍을 담는다 (단조 감소 유지).

새 사람 키 `h`가 들어올 때:
1. `while 스택 비지 않음 && top.키 ≤ h`:
   - `ret += top.개수` (그 그룹 전원이 h와 1쌍씩 보임)
   - top.키 == h 이면 `cnt = top.개수 + 1` (같은 키 묶음 누적), 아니면 `cnt = 1`
   - pop
2. pop 다 한 뒤 스택에 누군가 남아있으면(= h보다 큰 사람이 뒤에 있음) `ret++` (그 큰 사람과도 1쌍)
3. `(h, cnt)` push

- **`ret`는 반드시 `long long`** — 최대 약 n(n-1)/2 ≈ 1.25×10¹¹ 라 int 오버플로.

## 잘한 부분
- 강의 후 (키, 개수) 구조를 **안 보고 재현**해서 완주 (그대로 베끼지 않음)
- O(n²)면 TLE라는 걸 스스로 시간복잡도 계산으로 판단하고 접근을 바꿈
- `ret` long long 선택 (오버플로 회피)

## 막혔던 포인트 / 실수 모음
강의 보기 **전** 첫 시도 (인덱스 스택):
1. **`ret += i - st.top()` — 인덱스 거리를 더함.** 보이는 쌍은 *pop 1회당 1쌍*이지 자리 번호 차이가 아니다. (반례 `3 1 2 4`에서 8이 나옴, 정답 5)
2. **같은 키를 못 셈.** 인덱스만 담으니 `2 2 2` 같은 묶음(답 3)을 처리할 방법이 없었음 → 그래서 **(키, 개수) 쌍**을 담아야 한다는 게 이 문제의 전부.
3. `st.push(0)`을 **두 번** 호출 (인덱스 0 중복 삽입)
4. `while(flag==0 || st.empty())` — 조건이 거꾸로. 스택 비면 멈춰야 하는데 오히려 계속 돌아 빈 스택 접근 크래시.

강의 보고 (키, 개수)로 다시 짠 **후** 남았던 버그:
5. **`while(!st.size() && ...)` — `!` 오타로 조건 반전.** `!st.size()`는 "스택이 비었을 때만" true → 들어가자마자 `st.top()`으로 빈 스택 접근 → **세그폴트**. 차 있을 땐 루프가 아예 안 돎. → `while(st.size() && ...)`로 수정.
6. while 종료 후 `if(temp < st.top().first)` — 전부 pop 해 **스택이 비면** `st.top()` 빈 접근. → `if(st.size())` 가드로 수정 (어차피 루프 종료 시 남은 top은 항상 temp보다 큼).

## 배운 점
- **모노토닉 스택의 단 하나의 그림**: 왼→오 한 번 훑으며 스택엔 "아직 결판 안 난 후보"만 쌓는다. 새 원소가 들어오면 끝장난 애들을 pop하고, **그 pop 순간이 정답을 세는 순간**.
- 항상 두 질문: ① 스택에 뭘 담지(미래에 쓸 후보가 뭐냐) ② 새 원소가 들어오면 누가 결판나고 그때 뭘 세냐.
- 이건 2206에서 "큐에 (w,y,x) 무엇을 담을지" 막혔던 것과 **같은 종류의 약점**. 자료구조만 큐↔스택 다를 뿐 "통에 무슨 상태를 담아야 미래 판단이 되는가"가 본질.
- 빈 컨테이너 접근(`top()`/`front()`)은 단골 크래시 — `size()`/`empty()` 가드 + 조건의 `!` 방향을 항상 의심.

## 코드 리팩토링 (강의 전 → 강의 후)
| | 강의 전 (틀림) | 강의 후 (AC) |
|---|---|---|
| 스택에 담는 것 | 인덱스 | **(키, 개수)** 쌍 |
| 카운팅 | `ret += i - st.top()` (인덱스 거리) | pop당 `ret += 개수`, 큰 사람 뒤에 있으면 `ret++` |
| 같은 키 | 처리 불가 | `cnt = 개수 + 1`로 묶음 누적 |
| 시간복잡도 | (애초에 동작 안 함) | O(n) |

## 최종 AC 코드
```cpp
#include<bits/stdc++.h>
using namespace std;
int n, temp;
long long ret;
stack<pair<int,int>> st;   // (키, 개수)

int main(){
    ios_base::sync_with_stdio(false);
    cin.tie(NULL); cout.tie(NULL);
    cin >> n;
    for(int i = 0; i < n; i++){
        cin >> temp;
        int cnt = 1;
        while(st.size() && st.top().first <= temp){
            ret += st.top().second;
            if(st.top().first == temp) cnt = st.top().second + 1;
            else                       cnt = 1;
            st.pop();
        }
        if(st.size()) ret++;        // 뒤에 더 큰 사람과 1쌍
        st.push({temp, cnt});
    }
    cout << ret << '\n';
    return 0;
}
```
