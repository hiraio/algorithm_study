# BOJ 5430 — AC (덱 + 방향 플래그)

**날짜**: 2026-06-04
**유형**: 자료구조 (deque) / 시뮬레이션 최적화
**(주의: 4주차 Day5 문제지만 비트마스킹 아님)**

## 핵심 아이디어
명령 `R`(뒤집기) / `D`(앞 원소 버리기)를 배열에 적용.
- **naive로 매 `R`마다 `reverse()` 하면 O(p·n)** = 10만 × 10만 = 100억 → **시간초과**
- → 핵심: **뒤집기를 실제로 하지 않는다.** `bool rev` 플래그만 토글
  - `rev==false`면 `D`는 `pop_front`, `rev==true`면 `pop_back` (deque 양끝 O(1))
- `R`은 출력 직전에 한 번만 실제 `reverse` (rev가 true일 때)
- 빈 덱에 `D` → `error`

## 시간복잡도 분석 (이번에 직접 따짐)
- `reverse()`: O(n), `vector` 앞 삭제(`erase(begin)`): O(n) → 둘 다 함정
- `deque` 양끝 push/pop: **O(1)** → 이걸로 전체 O(p + n) 달성
- → 치트시트로 정리: `참고자료/시간복잡도_치트시트.md`

## 잘한 부분
- "곧이곧대로 구현하면 왜 터지나"를 **곱셈(명령수 × 명령당 비용)으로 미리 판단** 후 deque+flag 설계
- 입력 파싱: `[`, `]` skip + 숫자 누적, `,` 만나면 push, 루프 끝나고 마지막 원소 push (빈 배열 `[]`은 x>0 체크로 자연 처리)
- 출력에서 마지막 원소만 콤마 없이 분기 처리

## 배운 점
- **"앞에서 자주 빼는" 연산 = vector 말고 deque** (vector 앞 삭제는 O(n))
- 뒤집기 연산은 **방향 상태만 들고 다니다가 마지막에 한 번** 실현하면 됨 (실제 뒤집기 회피)
- N 보고 허용 복잡도부터 판단하는 습관 → O(p·n) 불가 즉시 인지
