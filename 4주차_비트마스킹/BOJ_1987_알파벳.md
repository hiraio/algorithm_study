# BOJ 1987 — 알파벳 (비트마스킹 풀이)

**날짜**: 2026-05-28
**유형**: DFS + 비트마스킹
**관련 파일**: `3주차_BFS_백트래킹/BOJ_1987_알파벳.md` (2026-04-06, DFS 백트래킹 + 배열 visited 버전)

## 핵심 테크닉
- 알파벳 26개 사용 여부를 `int` 한 정수의 26비트로 표현
- `mask & (1 << c)`로 이미 방문한 알파벳인지 판단
- DFS 매개변수에 `mask | (1 << c)`로 새 마스크를 넘김 → 별도 복원 불필요 (caller의 mask는 변경되지 않음)

## 막혔던 포인트
1. **비트마스킹으로 접근 자체에 애먹음** — 4/6 풀이는 `int alpha[26]` 배열로 마킹/언마킹하는 백트래킹이라 손에 잡혔는데, "26칸 배열 → 정수 한 개의 26비트"로 사고를 옮기는 게 안 떠올랐음. 19942(다이어트)에서 잡혔던 "집합=정수 하나" 감각이 같은 알파벳 집합 문제로 옮겨붙는 데 시간 걸림
2. **`&` 연산자로 방문 판단** — `if (mask & (1 << c))` 결과가 0이면 미방문, 0이 아니면 방문임을 자연어로 매핑하는 게 헷갈림. `==`로 비교해야 할지 그냥 truthy 체크로 둘지, 비트가 켜져 있다는 게 visited라는 게 직관적으로 안 와닿음
3. **DFS 매개변수로 `|` 넘기기** — 4/6 백트래킹 버전은 `alpha[c]++` → 재귀 → `alpha[c]--` 명시적 복원이었음. 비트마스킹은 `dfs(ny, nx, depth+1, mask | (1 << c))` 한 줄로 끝나는데, "복원 안 해도 되나?"가 자꾸 걸림. 매개변수로 새 값을 넘기면 자기 함수의 `mask`는 그대로라 자동 복원되는 원리를 머리로 이해해도 손으로 쓸 땐 멈칫함

## 배운 점
1. **비트마스킹 = 백트래킹의 "자동 복원" 버전** — 배열 visited는 마킹/언마킹 쌍이 필수지만, 비트마스크는 매개변수로 새 값을 넘기는 순간 caller의 상태는 안 건드려짐. 14620에서 배운 "sum + cost를 매개변수로 넘기는 자동 복원" 패턴과 같은 원리
2. **`&`(읽기) vs `|`(쓰기) 의미 매핑** — 11723에서 정리한 "AND = 정보 추출, OR = 상태 설정" 관용구가 visited 체크에도 그대로 적용. `mask & bit` → "이 비트 켜져 있나?", `mask | bit` → "이 비트 켜라". XOR는 토글이라 이 문제엔 안 씀
3. **3주차 DFS 백트래킹 → 4주차 비트마스킹 같은 문제 재풀이의 가치** — 동일 문제를 다른 도구로 풀면서 "visited를 배열이 아닌 정수 한 개로 들고 다닐 수 있다"는 감각이 구체화됨. 알파벳 26개라는 작은 N이 비트마스킹의 신호였음

## 4/6 DFS 백트래킹 버전과의 차이
| 항목 | 4/6 (3주차) | 5/28 (4주차) |
|------|------------|--------------|
| visited 표현 | `int alpha[26]` 배열 | `int mask` 한 정수의 26비트 |
| 마킹 | `alpha[c]++` | `mask | (1 << c)` |
| 방문 체크 | `if (alpha[c])` | `if (mask & (1 << c))` |
| 복원 | `alpha[c]--` (명시) | 매개변수로 새 값 넘기기 (자동) |
| 상태 전달 | 전역 배열 공유 | 함수 인자로 전달 |
