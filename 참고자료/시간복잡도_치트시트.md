# 시간복잡도 치트시트 (코테용)

> 한 줄 요약: **N(입력 크기)을 보고 → 쓸 방법을 고른다.**

---

## 핵심 원리 (이거 하나에서 다 나온다)

- 컴퓨터는 **1초에 약 1억 번(10^8)** 연산한다.
- 코테 제한은 보통 **1~2초**.
- → 내 코드가 도는 횟수가 **1억을 넘으면 시간초과**.

> 복잡도란 = **"입력 N개일 때 코드가 몇 번 도는가"**

---

## STEP 1. 내 코드가 몇 번 도는지 세는 법

**for문 중첩 겹수 = 복잡도**

| 코드 구조 | 복잡도 |
|-----------|--------|
| 1겹 | O(N) |
| 2겹 (N × N) | O(N²) |
| 3겹 | O(N³) |

자주 쓰는 도구들:

| 도구 | 복잡도 |
|------|--------|
| 정렬 `sort()` | O(N log N) |
| 이분탐색 | O(log N) |
| 완전탐색 (부분집합/비트마스킹) | O(2^N) |
| 순열 다 해보기 | O(N!) |

---

## STEP 2. N을 보고 "허용 복잡도" 판단

문제에서 **N 최댓값**을 먼저 본다. 그게 곧 답.

| N 최댓값 | 도는 횟수 | 쓸 수 있는 방법 |
|----------|-----------|-----------------|
| 10 이하 | N! | 순열 완전탐색 |
| 20 이하 | 2^N | 부분집합 / 비트마스킹 |
| 500 이하 | N³ | for 3겹 |
| 10,000 이하 | N² | for 2겹 |
| 10만 이하 | N log N | 정렬 / 이분탐색 / 힙 |
| 100만 이상 | N | for 1겹만 |

**읽는 법:**
- N이 크면 (10만↑) → 빠른 한 겹 방법만 가능
- N이 작으면 (20↓) → 무식하게 다 해봐도 됨

---

## 왜 이 경계인가 (O(N²) 기준 확인)

| N | N² (도는 횟수) | 1억 넘나? |
|------|------|------|
| 1,000 | 100만 | ✅ 안전 |
| 10,000 | 1억 | ⚠️ 빠듯 |
| 100,000 | 100억 | ❌ 초과 |

> "N이 만 단위인데 2중 for문 = 터진다"

---

## log N이란? (반으로 쪼개는 횟수)

> **log₂ N = "N을 몇 번 반으로 쪼개야 1이 되나" = "2를 몇 제곱해야 N이 되나"**
> (`2ˣ = N` 일 때 그 `x`)

**업다운 게임**으로 기억: 1~100 숫자 맞히기 → 매번 범위 반으로 → 100→50→25→…→1, 약 7번. 이 7이 `log₂100`.

핵심은 **로그가 미친듯이 천천히 큰다**는 것:

| N | log₂ N (반 쪼개기 횟수) |
|------|------|
| 8 | 3 |
| 1,000 | 약 10 |
| 100만 | 약 20 |
| 10억 | 약 30 |

> N이 **10억**이어도 log는 고작 **30**. "거의 안 자라는 작은 수"로 느껴도 됨.

**그래서 O(N log N) = N에 작은 수(log N)를 살짝 곱한 것 → N보다 약간 느릴 뿐, N²과는 비교 불가.**

| 복잡도 (N=1억) | 도는 횟수 | 결과 |
|------|------|------|
| O(N) | 1억 | 순식간 |
| O(N log N) | 약 27억 | 1~2초, 통과 ✅ |
| O(N²) | 10^16 | TLE ❌ |

**로그가 튀어나오는 패턴 = "반으로 쪼개기"가 들어갈 때**: 이분탐색(범위 반씩), 정렬(병합/퀵), 힙·균형트리(넣고빼기 1회 log N).
(밑은 2지만 Big-O에선 밑 상관없음 — 상수배라 무시.)

---

## STEP 3. STL 함정 (실수 단골)

같은 "삽입/삭제"도 **어디서 하느냐**로 비용이 갈린다.

| 연산 | 비용 | 주의 |
|------|------|------|
| vector 뒤에서 넣기/빼기 | O(1) | |
| vector 앞·중간 넣기/빼기 | **O(N)** ⚠️ | 나머지 다 밀림 |
| deque 양끝 넣기/빼기 | O(1) | |
| set / map 삽입·검색 | O(log N) | 정렬됨 |
| unordered_map 삽입·검색 | O(1) 평균 | |

> 교훈: "앞에서 자주 빼야 하면 vector 말고 **deque**"

---

## 적용 예 — BOJ 5430 (AC)

- N(명령·배열 길이) = 10만 → **O(N) 한 겹만 허용**
- ✗ 명령마다 `reverse()` = 10만 × 10만 = **100억** → 초과
- ✓ 뒤집기를 실제로 안 하고 **"방향 flag"만 토글**, 버리기는 **deque 양끝 O(1)**
